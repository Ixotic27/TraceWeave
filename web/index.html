How it works

Here’s what happens to your logs, from upload to export.

Field suggestions

The saved model works locally without a cloud AI service. It can leave uncertain fields unassigned.
1

Add logs from a device

Export a log file from your firewall or gateway, then choose Add logs. Give the device a name you’ll reuse for future uploads.

Upload a file up to 2 MB, or paste its contents. One log per line works for most files. Automatic detection also recognizes a complete JSON object, flat XML, or a CSV header and one row.

2

Tell us what the fields mean

Different devices use different field names. For example, a field may mean Source IP (where traffic came from) or Destination IP (where it was going).

Open a log marked Needs review, check the suggestions against your device’s documentation, and save. Those settings apply to matching logs from the same source, including future uploads.

3

Take your results with you

Ready to export means the required fields have been reviewed and their values validated. Export downloads these records as NDJSON: one JSON object per line.

Each exported record includes its original content and the origin of each processed field. Records that need review or couldn’t be processed stay saved, but are excluded from export.

?

When something needs attention

Format changed: the source’s fields or value types changed. Review the new structure before exporting.

Couldn’t process: a format or value isn’t supported. Open the log to see the reason and download its original content.

Required fields depend on the event type. Generic firewall decisions need Source IP, Destination IP, and Action; supported passive connections and alerts do not require an invented action. Some vendor-specific formats need an additional parser. There is no direct device connection yet; add files or send logs to the local ingestion API.

Need connection help? Start run.ps1 in the project folder, then open your local workspace. A static hosting page cannot run the log-processing server.
